# ニュース・センチメント分析プロンプト

## この教材で身につくこと

- ニュース記事本文に基づいたセンチメント判定プロンプトの設計方法
- 確信度（confidence）を出力させることで判定の不確実性を可視化する手法
- JSON形式で構造化出力を得るプロンプトの書き方

## 概要

株価に影響するニュースは日々大量に発生します。すべてを人手で読むのは
非効率なため、LLMに「ポジティブ/ネガティブ/中立」を判定させ、
一次スクリーニングに使うことがあります。

ここで重要なのは、判定の根拠を記事本文に限定することです。
見出しや銘柄名だけを渡すと、モデルは学習データに含まれる
過去の記憶で判定してしまい、最新の実態と乖離するおそれがあります。

## 位置づけ

前の教材（01-earnings-summary-prompts.md）では「一次情報のみを
根拠にする」原則を決算短信に適用しました。この教材では同じ原則を
ニュース記事に適用し、さらに構造化出力（JSON）を組み合わせます。

構造化出力の詳細な技法は03-data-api/03-structured-output.mdで
扱います。この教材はその前段として、プロンプト側の工夫を学びます。

## 主要概念・パラメータ解説

| 要素 | 目的 | 具体例 |
|------|------|--------|
| 記事本文の全文提供 | 見出しだけの誤判定を防ぐ | 本文をプロンプトに丸ごと埋め込む |
| 判定根拠の限定 | モデルの一般知識混入を防ぐ | 「以下の記事本文のみに基づいて判定」 |
| confidenceの出力 | 判定の不確実性を可視化する | 0.0〜1.0の数値で確信度を出力させる |
| JSON形式の指定 | 後続処理でパースしやすくする | `sentiment`, `confidence`, `reason` の3フィールド |
| reasonの一文限定 | 判定根拠を検証可能にする | 「本文中の該当箇所を要約して1文で」 |

## 実ソースコード（Python / プロンプト例）

### 悪い例

記事本文を渡さず、見出しと企業名だけでセンチメントを
推測させています。モデルの一般知識やその企業への印象に
引きずられるリスクがあります。

```text
「〇〇株式会社」に関するこのニュース見出しは、株価にとって
ポジティブですか、ネガティブですか？

見出し: 〇〇株式会社、新工場建設を発表
```

### 良い例

記事本文全文を渡し、判定根拠をその本文のみに限定しています。
出力はJSON形式で、confidenceとreasonを含めています。

```text
あなたはニュース記事の株価インパクトを判定するアシスタントです。
以下の【記事本文】のみに基づいて、短期的な株価への影響を判定して
ください。記事に書かれていない情報や一般的な知識で判定しないで
ください。

出力は次のJSON形式のみとし、他の文章は出力しないでください。

{{
  "sentiment": "ポジティブ" | "ネガティブ" | "中立",
  "confidence": 0.0から1.0の数値,
  "reason": "判定根拠を本文から1文で要約"
}}

【記事本文】
{article_text}
```

### プロンプトテンプレートの適用

```python
import json

NEWS_SENTIMENT_PROMPT = """\
あなたはニュース記事の株価インパクトを判定するアシスタントです。
以下の【記事本文】のみに基づいて、短期的な株価への影響を判定して
ください。記事に書かれていない情報や一般的な知識で判定しないで
ください。

出力は次のJSON形式のみとし、他の文章は出力しないでください。

{{
  "sentiment": "ポジティブ" | "ネガティブ" | "中立",
  "confidence": 0.0から1.0の数値,
  "reason": "判定根拠を本文から1文で要約"
}}

【記事本文】
{article_text}
"""


def build_news_sentiment_prompt(article_text: str) -> str:
    """記事本文を埋め込み、センチメント判定プロンプトを組み立てる。"""
    return NEWS_SENTIMENT_PROMPT.format(article_text=article_text)


def call_llm(prompt: str) -> str:
    # 実装は 03-data-api/02-llm-api-integration.md 参照
    # JSONモード等の構造化出力は 03-data-api/03-structured-output.md 参照
    raise NotImplementedError


def parse_sentiment_response(response_text: str) -> dict:
    """LLM応答のJSON文字列をパースする。壊れたJSONは呼び出し側で検知する。"""
    return json.loads(response_text)


if __name__ == "__main__":
    article = "（実際にはニュース配信APIから取得した記事本文全文を渡す）"
    prompt = build_news_sentiment_prompt(article)
    response = call_llm(prompt)
    result = parse_sentiment_response(response)
    print(result)
```

### 実行結果例

```json
{
  "sentiment": "ポジティブ",
  "confidence": 0.72,
  "reason": "新工場稼働により生産能力が2倍になると記事内で明言されており、増収要因として好感される可能性が高い。"
}
```

## 演習課題

1. 「悪い例」のプロンプトを実行した場合に、本文なしで
   モデルが判定できてしまう理由（何を根拠にしているか）を考えてください。
2. `confidence` が0.5前後の場合に、後続処理でどう扱うべきかを
   設計してください（例: 人手レビューに回す等）。
3. `reason` の文字数を制限する指示を追加してみてください。
