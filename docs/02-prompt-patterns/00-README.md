# 02. Prompt Patterns - プロンプト設計パターン

このカテゴリでは、株式投資のリサーチの現場で繰り返し使える、
具体的な4つのプロンプトパターンを学びます。

01-fundamentalsで学んだLLMの特性（ハルシネーション・知識カットオフ）を
踏まえ、実際に「使える」プロンプトの設計方法を身につけます。

## 学習目標

- 決算短信を構造化して要約するプロンプトを設計できる
- ニュース記事から根拠付きのセンチメント判定を引き出せる
- 自然言語の条件をスクリーニング用の構造化フィルタに変換できる
- 複数データを統合し、事実と考察を分離したレポートを生成できる
- 「良い例」と「悪い例」の違いを、自分のプロンプトに応用できる

## 共通する設計原則

4つの教材はすべて、次の4つの原則に基づいています。

| 原則 | 内容 |
|------|------|
| 一次情報を渡す | モデルの記憶に頼らず、実際のテキスト・データをプロンプトに含める |
| 出力を構造化する | 自由記述ではなく、パース可能な形式（箇条書き・JSON等）を指定する |
| 確信度を言わせる | 不確実な場合はその旨を明示させ、断定を避けさせる |
| 指示とデータを分離する | 指示文と入力データの境界を明確にし、混同を防ぐ |

これらの原則は、決算要約・ニュース分析・スクリーニング・レポート生成の
どの用途でも共通して有効です。以降の教材では、この原則がどのように
プロンプトの文言に反映されるかを、具体例で確認していきます。

## 学習の進め方

01 → 04 の順に進めることを推奨します。

各教材は「悪い例」と「良い例」のプロンプトを対比して示します。
実際に自分の手で書き換えながら読むと理解が深まります。

すべてのプロンプト例は `text` コードブロック、Pythonコードは `python`
コードブロックで区別しています。実行結果例はあくまで想定出力であり、
実際のLLMの応答とは異なる場合があります。
