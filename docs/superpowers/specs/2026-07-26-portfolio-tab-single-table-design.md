# 保有銘柄ポートフォリオタブの表を1つに簡潔化

## 背景・課題

`app/app_tabs/portfolio_tab.py` の「保有銘柄ポートフォリオ」タブには、当初2つの表が並んでいた。

1. 編集可能な `st.data_editor` テーブル（銘柄コード・銘柄名・保有株数・取得単価。追加/編集/削除/保存を担う）
2. 「銘柄詳細を見る」の一覧テーブル（保有銘柄ごとに行を並べ、各行に銘柄コード・銘柄名・「詳細」ボタンを表示し、クリックすると銘柄詳細ダイアログを開く）

同じ保有銘柄の情報が2つの表に重複して表示されており、画面が冗長。1つの表にまとめて簡潔にしたい。

（初回改修では表2を「セレクトボックス＋詳細ボタン」に置き換えたが、「銘柄詳細を見る」という機能・見出し自体をなくしたいという要望を受け、以下の方針に変更した。）

## 方針

`app/screening_tab.py` や `app/ranking_tab.py` で既に使われている「`st.dataframe` + `on_select` + `handle_table_selection`（行クリックで詳細ダイアログを開く）」パターンに統一する。

- メインの表を `st.data_editor`（複数行一括インライン編集）から、読み取り専用の `st.dataframe`（銘柄コード・銘柄名・保有株数・取得単価、`on_select="rerun"`, `selection_mode="single-row"`）に変更する。
- 行をクリックすると `handle_table_selection` 経由で銘柄詳細ダイアログが開く。「銘柄詳細を見る」の見出し・セレクトボックス・詳細ボタンは廃止する。
- 選択中の行がある場合のみ、その1銘柄の「保有株数」「取得単価」を編集する `number_input` 2つ、および「更新」「削除」ボタンを表の下に表示する。「更新」「削除」はクリック時に即座に `save_holdings` でファイル保存する。
- 複数行を一度にスプレッドシート的に編集する一括保存（旧「保有銘柄を保存」ボタン）は廃止する。
- 銘柄の追加（「銘柄を検索して追加」）は変更しない。追加直後は保有株数0・取得単価0の行としてすぐ一覧に反映され、その行を選択して更新することで数値を入力する。

## 変更範囲

`app/app_tabs/portfolio_tab.py` の `render_portfolio_tab()` 内、一覧表示・編集・削除に関わる部分のみ。
それ以外（データ保存の実装先である `portfolio_management/storage.py`、AIレビュー生成処理、参照ニュース表示など）は変更しない。

## 影響を受けないもの

- `portfolio_management/storage.py`（保存・読込ロジック）
- `holdings.json` のデータ構造
- 他タブ・他モジュール（`handle_table_selection` は既存の共有ヘルパーをそのまま再利用する）

## テスト

このタブはStreamlit UIのため、`streamlit.testing.v1.AppTest` を使い、`holdings.json` のテスト用コピーに対して以下を確認する（実データは変更しない）。

- 初回描画で例外が出ないこと、表が1つだけであること
- 行が選択されている状態で「保有株数」「取得単価」の入力欄と「更新」「削除」ボタンが表示されること
- 「更新」クリックでテスト用ファイルに新しい値が保存されること
- 「削除」クリックでテスト用ファイルから該当行が消えること

なお、`st.dataframe` の行クリック選択（`on_select`）自体はAppTestでシミュレートできないため、その部分は既存タブ（スクリーニング・ランキング）で使われている実装をそのまま再利用することで担保する。実際のクリック動作はブラウザでの目視確認が望ましい。
