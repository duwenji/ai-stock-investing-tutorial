# セクターローテーション UI説明強化 設計書

## 概要・目的

[セクターローテーションタブ](2026-07-20-sector-rotation-design.md)（相関ヒートマップ・リード/ラグ表・AIコメント）と、今回追加した[ウェーブレット分析セクション](2026-07-21-sector-rotation-wavelet-design.md)には、「コヒーレンス」「周期帯」「リード・ラグ」など、投資初心者には分かりにくい専門用語が多い。本機能では、コードやロジックを変更せず、UI上の説明（ツールチップ・展開式の解説）のみを追加し、ユーザーが各要素の意味を理解しやすくする。

売買の推奨・指示は行わない（[DISCLAIMER.md](../../../../DISCLAIMER.md)準拠）という既存方針は変更しない。

## スコープ

- v1で実装する: セクターローテーションタブ内の全ウィジェット・セクションへの説明追加（`app.py`のみ変更）
  - 各入力ウィジェット（selectbox・checkbox・button）への`help`引数（ホバーで表示される？アイコンツールチップ）
  - 各`st.subheader`への`help`引数（セクション見出しの意味を短く説明）
  - 2箇所の`st.expander`による詳細解説（「リード・ラグの読み方」「ウェーブレット分析とは？」）
- v1で実装しない:
  - ロジック・計算内容の変更（`sector_analysis/correlation.py`, `sector_analysis/wavelet.py`, `prompt_patterns/sector_rotation.py`は変更しない）
  - 他タブ（ポートフォリオ・スクリーニング・バックテスト・一括バックテスト）への説明追加
  - 用語集ページやアプリ全体のオンボーディングフローの新設

### 2. 展開式解説（1）— 「リード・ラグの読み方」

**配置:** `st.dataframe(pairs_df, ...)`（リード・ラグ上位ペア表）の直後、`st.subheader("相関上位5ペアのAIコメント")`の直前。

```python
with st.expander("リード・ラグの読み方"):
    st.markdown(
        "「先行業種」の値動きに、「追随業種」が「ラグ（営業日）」で示した日数だけ"
        "遅れて追随する傾向が、指定した期間の株価データから確認されたことを示します。\n\n"
        "例えば「先行業種: 建設・資材、追随業種: 機械、ラグ: 0日、相関係数: 0.87」であれば、"
        "建設・資材セクターの値動きと機械セクターの値動きが、同じ営業日にほぼ同じ方向へ"
        "動く傾向が強かったことを意味します。\n\n"
        "**注意:** 上位ペアの多くはラグ0日（同時相関）になりやすい傾向があります。"
        "これは業種固有の先行・追随関係というより、市場全体の地合い（同じ日に多くの業種が"
        "一緒に動く傾向）を反映している可能性があります。特定の周期の長さ"
        "（短期・中期・長期）ごとに、より業種固有の先行・追随関係を確認したい場合は、"
        "下部の「ウェーブレット分析」もあわせてご覧ください。"
    )
```

- 「市場全体の地合いに偏る」という注意書きは、[ウェーブレット分析の実装計画](2026-07-21-sector-rotation-wavelet.md)のTask 3手動確認で実際に観測された挙動に基づく、正確な説明である

### 3. 展開式解説（2）— 「ウェーブレット分析とは？」

**配置:** ウェーブレット分析セクションの`st.caption(...)`の直後、`sector_options`の業種数チェック（`if len(sector_options) < 2:`）の前。業種数に関わらず常に表示する。

```python
with st.expander("ウェーブレット分析とは？"):
    st.markdown(
        "通常の相関分析は「期間全体で1つの数値」を計算しますが、実際の値動きには"
        "短い周期（数日〜2週間程度）の動きと、長い周期（1〜6か月程度）の動きが"
        "混ざっています。ウェーブレット分析は、この値動きを周期の長さ"
        "（短期・中期・長期）ごとに分解し、周期ごとに「どちらの業種が先に動いたか」"
        "「どれくらい確からしい関係か（コヒーレンス）」を計算する手法です。\n\n"
        "**周期帯の目安**\n"
        "- 短期: 4〜10営業日程度（1〜2週間の値動き）\n"
        "- 中期: 10〜40営業日程度（2週間〜2か月の値動き）\n"
        "- 長期: 40〜120営業日程度（2〜6か月の値動き）\n\n"
        "**下のヒートマップの読み方**\n"
        "- 横軸: 日付\n"
        "- 縦軸: 周期の長さ（営業日）\n"
        "- 色: 正（青系）なら業種Aが先行、負（赤系）なら業種Bが先行\n"
        "- 色の濃さ: 関係の確からしさ（コヒーレンス）。薄いほど確からしさが低く、"
        "参考程度に留めてください\n\n"
        "下部の「支配的ラグ」の折れ線グラフは、選んだ周期帯の中でコヒーレンスの"
        "高い部分を重視した、平均的な先行・遅行日数の推移を示します。0より上なら"
        "業種Aが先行、0より下なら業種Bが先行していたことを意味します。"
    )
```

## エラーハンドリング

本機能はUI上の静的な説明文の追加のみであり、新規のエラーケースは発生しない。既存のエラーハンドリング（データ不足・計算失敗時の`st.warning`/`st.error`等）はそのまま維持する。

## テスト方針

- ロジック変更を伴わないため、新規の自動テストは追加しない。既存の`uv run pytest`が全件PASSすることのみ確認する
- `uv run python -m streamlit run app.py`を起動し、以下を手動確認する:
  - 各ウィジェットにホバーすると？アイコンとツールチップ文言が表示されること
  - 「リード・ラグの読み方」「ウェーブレット分析とは？」の2つのexpanderが、初期状態では折りたたまれており、クリックで開閉できること
  - 展開した内容がMarkdownとして正しくレンダリングされる（太字・箇条書きが崩れない）こと
  - ブラウザコンソールにエラーが出ていないこと
